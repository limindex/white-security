# 화이트 보안 — 이슈 목록

아래에서 지금 하는 일과 맞는 묶음을 고르고, 해당 이슈 파일만 읽는다.

## AI를 쓸 때

언제 읽나: AI에게 문서·웹페이지·메일을 읽히거나 요약시킬 때

- [WS-PI-001 간접 프롬프트 삽입](ai-use/WS-PI-001.md) — AI에게 남이 쓴 글(웹페이지·메일·PDF)을 읽히면, 글 속에 숨은 문장을 AI가 명령으로 알아듣고 엉뚱한 답을 하거나 엉뚱한 일을 할 수 있다. 이것을 간접 프롬프트 삽입(간접 프롬프트 인젝션)이라고 한다. 프롬프트는 AI에게 주는 지시문이다.

## 긁어 오고 읽을 때

언제 읽나: 외부 URL·파일·XML을 가져와 읽거나 파싱할 때

- [WS-XML-001 XML 외부 개체 참조·엔티티 폭탄](fetch/WS-XML-001.md) — XML(태그로 내용을 감싸 적는 데이터 형식) 파일을 읽는 프로그램이 파일 속 특별한 선언을 그대로 따르면, 서버의 비밀 파일이 새어 나가거나 작은 파일 하나가 서버 메모리를 다 써서 서비스가 멈춘다. 진단가이드 이름은 '부적절한 XML 외부 개체 참조'다.

## 웹 기본

언제 읽나: 입력을 받아 DB·화면·파일로 넘기는 웹 기능을 만들 때

- [WS-INJ-001 SQL 삽입](web/WS-INJ-001.md) — 검색창이나 로그인 칸에 넣은 글자가 DB(데이터를 쌓아 두는 창고)에 보내는 명령문(SQL)에 그대로 끼워지면, 그 글자가 명령이 되어 남의 데이터를 꺼내거나 지운다. 진단가이드 이름은 'SQL 삽입'이다.

## 로그인·권한

언제 읽나: 로그인·권한·'내 것만 보기' 기능을 만들거나 고칠 때

- [WS-AUTH-001 부적절한 인가](auth/WS-AUTH-001.md) — 로그인했는지만 확인하고 '이게 이 사람 것인지'는 확인하지 않으면, 주소창의 숫자만 바꿔도 남의 주문·파일·개인정보가 열린다. 진단가이드 이름은 '부적절한 인가'다. 인가는 이 사람이 이 일을 해도 되는지 허락하는 일이다. 흔히 IDOR라고도 부른다.

## 설정·배포

언제 읽나: API 키·설정 파일을 다루거나 서버에 올릴 때

- [WS-SEC-001 비밀키·토큰 노출](deploy/WS-SEC-001.md) — API 키(서비스를 쓸 수 있는 비밀 열쇠)나 DB 비밀번호를 코드에 그대로 적어 두면, 코드를 올린 곳·웹 화면·로그를 통해 남에게 보인다. 그 열쇠로 남이 내 돈과 데이터를 쓴다. 진단가이드 이름은 '하드코드된 중요정보'다.

## 의존성·공급망

언제 읽나: 패키지를 새로 설치하거나 버전을 올릴 때

- [WS-SUP-001 패키지 환각](supply/WS-SUP-001.md) — AI가 알려 준 패키지(남이 만들어 둔 코드 묶음) 이름이 사실은 AI가 지어낸 이름일 수 있다. 확인 없이 설치하면, 그 이름을 먼저 차지한 사람이 만든 코드가 내 컴퓨터와 서버에서 돌아간다.
